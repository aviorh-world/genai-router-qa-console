הקדמה — איך בודקים API במערכת הזאת?

כל Endpoint הוא פעולה שהמערכת מאפשרת לבצע. הבדיקה אינה רק “האם חזר 200”, אלא האם הבקשה התקבלה נכון, האם התוכן שהוחזר נכון, האם ה־state השתנה כשצריך, והאם שגיאות והרשאות מטופלות בצורה בטוחה.

איך מסווגים כשל AI?

המידע הנכון לא נמצא, Source/Chunk שגוי או רלוונטי דורג נמוך מדי.

ה־Chunk נכון, אבל ה־LLM ניסח תשובה שגויה/חסרה.

התשובה מוסיפה או משנה טענה שאינה נתמכת ב־Context.

המערכת חשפה מידע/Source/Chunk שאסור למשתמש לראות או עקפה Guardrail.

ה־Router זיהה Intent לא נכון או שלח את השאלה לרכיב הלא נכון, למשל RAG במקום Text2SQL.

כללי Business / QA

מפת מערכת → מה זה אומר ל־QA

Text2SQL — איך הרכיב עובד ומה בודקים?

הרכיב מקבל שאלה בשפה טבעית, בונה Context לפי מאגרים/דומיינים, מייצר SQL באמצעות Gemini, מבצע BigQuery dry-run ויכול לתקן SQL לא תקין עד 3 ניסיונות. כאשר shouldFetchData=true הוא גם מריץ את השאילתה ומחזיר נתונים; תוצאה גדולה יכולה להישמר ב־GCS.

1Question → בחירת
2LLM →
3 + Validation / Retry
4Query Execution → Data או GCS אם התוצאה גדולה
5SQL/Data → תשובה אנושית

Endpoints מתועדים: POST /applications/queryanddata לשאלה→SQL/נתונים, ו־POST /applications/sql2text ל־SQL→הסבר ללא הרצת BigQuery.

Authentication: התיעוד מציין x-text2sql-api-key וכן JWT filter בשכבה שמעל. לפני אוטומציה יש לקבל Base URL ופרטי Auth של סביבת הבדיקה.

QA: לא מספיק שה־SQL חוקי. צריך לבדוק שהוא נכון לוגית, משתמש בטבלאות/פילטרים/joins הנכונים, מחזיר את הנתונים הנכונים, אינו חושף מידע אסור, ושהתשובה הסופית תואמת לנתונים.

אסטרטגיית בדיקות

תנאי כניסה ויציאה

Entry Criteria – אפשר להתחיל כש...

  • יש TSH Base URL.
  • יש משתמש ענן והרשאה ל־Router.
  • ניתן להפיק Identity Token תקין.
  • Swagger/Contract זמין.
  • קיימים App ID, User ID ו־Case ID לבדיקה.

Exit Criteria – אפשר לסיים כש...

  • כל בדיקות P0 הקריטיות עברו או שיש חריגה מאושרת ומתועדת.
  • אין תקלת אבטחה קריטית פתוחה.
  • תוצאות P1/P2 תועדו והסיכונים ידועים.
  • פערי Contract שחוסמים PASS/FAIL נסגרו או סומנו במפורש.
  • דוח הרצה הופק ונשמר.

סיכונים ותלויות

  • Token קצר־חיים עלול לפוג באמצע ריצה.
  • גישה ל־TSH תלויה ברשת ובהרשאות.
  • חלק מה־Expected Results עדיין אינם מוגדרים פורמלית ב־Swagger.
  • בדיקות State/Delete דורשות גישה או אישור על AlloyDB/לוגים.
  • בדיקות GenAI דורשות מקור אמת או SME כדי להכריע איכות עסקית.
